6. RESEARCH INTERPRETATION
==================================================

The experiment confirmed that the current semantic contract validator accepts additional fields when all required validation conditions are satisfied.

This behavior can be described as permissive field validation.

The validator checks whether required fields contain supported values but does not enforce an exact set of permitted field names.

The observed behavior is not automatically a defect.

Permissive validation may allow additional metadata to be included without modifying the validator.

However, it also means unexpected or misspelled additional fields may remain undetected when the required fields are otherwise valid.

This distinction is relevant to the reliability and interpretability of structured natural-language edge contracts.

==================================================
7. DESIGN CONSIDERATIONS
==================================================

Two possible validation policies are:

PERMISSIVE VALIDATION:
Accept additional fields as long as required fields are valid.

STRICT VALIDATION:
Reject fields that are not explicitly included in the contract schema.

The current prototype uses permissive validation.

A stricter policy could be evaluated in future work if exact schema enforcement becomes a requirement.

Changing the policy would require updating the validator and its associated tests.

==================================================
8. LIMITATIONS
==================================================

The experiment evaluated four predefined contract scenarios.

It did not test every possible additional field name or value type.

The experiment did not evaluate whether downstream components use, ignore, or interpret unexpected fields.

The results establish the validator's behavior for the tested scenarios, not the security or correctness of all possible contract extensions.

==================================================
9. CONCLUSION
==================================================

All four extra-field validation scenarios passed.

The experiment demonstrated that the existing semantic contract validator accepts unexpected top-level and condition-level fields when the required contract structure remains valid.

This behavior has been documented as a design characteristic and potential limitation of the current prototype.
